# Document Sidecar Schema

Every original document in `sources/` (PDF, JPG, RTF, DOCX, etc.) has a sidecar
`.md` file with the same base name. The sidecar holds extracted metadata, the
cleaned text, and pointers to companion files (translation, notes,
transcription).

The full template lives at `templates/document.md`.

## Filename

The sidecar matches the source filename's stem:

- `1937-family-letter.pdf` ↔ `1937-family-letter.md`
- `2003-grandma-obituary.jpg` ↔ `2003-grandma-obituary.md`

When the sidecar is generated by the scan pipeline before a final name is
chosen, it uses `YYYY-<slug>.md` (e.g., `1920-census-philadelphia.md`).

## Frontmatter

```yaml
---
title: "Descriptive Title"
type: ""                  # see Canonical types below
date: "YYYY-MM-DD"        # or YYYY for year-only
author: ""                # wikilink: "[[Firstname Lastname (YYYY)]]"
recipients: []            # array of wikilinks
related_people: []        # wikilinks to ALL people mentioned in the source
source: ""                # wikilink to the original file: "[[1937-family-letter.pdf]]"
languages: ["English"]    # array; non-English may need a translation companion
topics: []                # free-form tags: "immigration", "wedding", "schoolwork"
confidence: ""            # proven | probable | possible | uncertain — about the document, not its facts

# Companion files (optional — see "Companion files" below)
translation: ""           # bare filename with .md, NOT a wikilink
notes: ""
transcription: ""
content: ""

# For research artifacts
translator: ""            # name or "model + date"
covers: ""                # which pages / sections / scope
---
```

## Canonical `type:` values

Pick one. Do not invent new ones — if a new type is needed, add it to this
schema in a separate commit so all tooling stays in sync.

| Group | Types |
|---|---|
| Vital | `birth-record`, `death-record`, `marriage-record`, `burial-record`, `census` |
| Government / institutional | `immigration-record`, `naturalization-record`, `military-record`, `legal-record`, `financial-record`, `city-directory` |
| News & writing | `correspondence`, `obituary`, `eulogy`, `newspaper-clipping`, `memoir`, `sermon`, `diary` |
| Researcher artifacts | `family-group-sheet`, `genealogy-notes`, `research`, `historical-context` |
| Long tail | `yearbook`, `screenshot`, `map` |
| Media (photo-tagger) | `photo`, `portrait`, `tombstone`, `handwritten-fragment` |
| Sentinels | `blank-scan`, `unknown` |

## Body sections

```markdown
# {{title}}

## Description

(Brief prose describing the document — what it is, its provenance,
significance. Distinct from any quoted caption.)

## Caption

(If the source arrived with a sender-supplied caption — written on the back
of a photo, typed beside an image in a forwarded email — preserve it
**verbatim with attribution**:)

> Father in his grandfather's home where he grew up.

— [[Bart Aars-Nicolaysen (1941)]], email "One more find," May 19, 2026.

## Cleaned Text

(The OCR/transcribed text, cleaned of OCR artifacts but otherwise faithful to
the original. For images-only sources, omit this section.)

## Extracted Facts

(Bulleted list of facts pulled from the source, with citations to the source
itself — these will be merged into person files.)

## Related People

(Same as `related_people:` in frontmatter, but spelled out for human reading
in Obsidian.)

## Source

![[{{original-filename}}]]
```

## Companion files (translation, notes, transcription, content)

A primary sidecar can point at sibling `.md` files that hold supplementary
content — English translation of foreign-language text, researcher notes, a
verbatim transcription, or markdown content for an image-only primary.

**Four YAML keys are recognized by the document-tagger UI:**

```yaml
translation:   "<stem>-english-translation.md"
notes:         "<stem>-notes.md"
transcription: "<stem>-transcription.md"
content:       "<stem>-content.md"
```

**Critical: the value is a bare filename with `.md`, NOT a wikilink.** Both
forms work in Obsidian, but the document-tagger does a literal
`sources/<value>` lookup and does not append `.md` — so
`[[foo-translation]]` (Obsidian shorthand) silently misses the file.

- ✅ `translation: "1937-family-letter-english-translation.md"`
- ❌ `translation: "[[1937-family-letter-english-translation]]"`

## Sibling-suffix detection

The tagger build script auto-filters companions out of the primary doc list
via these stem suffixes. Pick one when naming a companion file:

`-translation`, `-english-translation`, `-notes`, `-transcription`, `-content`

## Captions

When a source arrives with a sender-supplied caption, preserve it **verbatim
with attribution** in the `## Caption` block. The caption is a primary
statement of identity by a family member and is genealogically valuable.
Never paraphrase. Render your own interpretive description separately in the
`## Description` block.
